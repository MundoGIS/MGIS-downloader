# Inloggning och användaradministration

Installera projektets npm-beroenden efter att eventuella merge-konflikter i `package-lock.json` har lösts. Skapa första admin **innan** appen görs åtkomlig externt: kör `npm.cmd run admin:init` i en interaktiv terminal på Windows-servern (`npm run admin:init` på andra system). Skriv användarnamn och ett eget lösenord på minst 6 tecken (högst 72 UTF-8-byte). Lösenordet skrivs dolt; det finns inget förvalt adminlösenord. Detta kommando kan bara skapa det första kontot. Efter inloggning kan admin skapa användare, byta namn, återställa lösenord, ändra roller och radera konton via `/admin.html`. Vanliga användare kan använda appen, men inte administrera konton eller radera nedladdningsmappar. Namnbyte behåller lösenordet; nästa inloggning använder det nya namnet.

Konton finns normalt i `data/users.json` (eller en absolut sökväg satt med `USERS_FILE`). Filen ligger utanför `public/`, är ignorerad av Git och innehåller **bcrypt-hashar**, aldrig lösenord i klartext. Restriktera filrättigheterna till tjänstekontot och administratörer och säkerhetskopiera vid behov. Använd inte GeoJSON för konton. Vanliga sessioner finns i serverminnet i upp till åtta timmar och upphör vid omstart. *Kom ihåg mig* ger en HttpOnly-cookie i 30 dagar och lagrar enbart sessionstokens **hash** i `data/remembered_sessions.json` (`SESSIONS_FILE` kan ändra sökvägen). Utloggning och byte av lösenord/roll återkallar berörda sessioner. JSON-filer och sessioner är avsedda för en Node-process, inte flera samtidiga instanser.

## HTTPS bakom IIS

Låt IIS terminera TLS och proxya via URL Rewrite/ARR till Node på `127.0.0.1:3004` (standardvärde för `HOST`/`PORT`). Behåll klientens publika `Host` eller vidarebefordra `X-Forwarded-Host`, samt `X-Forwarded-Proto: https`. Ta bort klientskapade forwarding-headers i IIS: Express litar bara på forwarding från loopback. HTTPS-sessioner får `Secure`, `HttpOnly`, `SameSite=Strict`-cookies. Begäranden som ändrar data kräver rätt origin. Exponera inte Node-porten på nätverket; undvik att proxycacha autentiserade sidor och API-svar. Verifiera själv IIS-konfiguration, certifikat, filrättigheter och säkerhetskopior vid driftsättning.

## Publicerade terrängtjänster

En **ny** XYZ-katalog är privat som standard. Under nedladdningskortet kan du markera **Public** för att ge anonym tillgång till bildtiles. Kataloger som publicerades före åtkomstinställningen förblir publika tills de ändras. När Public stängs av skapas en unik API-nyckel per tjänst. Den visas bara vid publicering, privatställning eller rotation: kopiera och förvara den säkert direkt. Servern lagrar bara en SHA-256-hash av nyckeln; förlorade nycklar måste roteras med **Ny API-nyckel**, vilket ogiltigförklarar den gamla direkt.

Hajk, Origo, QGIS (anslutning *XYZ Tiles*), Leaflet, OpenLayers och andra klienter med stöd för **XYZ** kan använda `/terrain/<alias>/tiles/{z}/{x}/{y}.png`. För en privat tjänst behövs `?api_key=<nyckel>` i HTTPS-URL:en eller `X-API-Key`-header där klienten stödjer den. WMS och WMTS erbjuds inte. Nycklar i URL:er kan sparas i IIS/proxyloggar, webbhistorik och klientkonfigurationer: skydda loggarna och sprid inte privata länkar. Endast uttryckligen publicerade bildtiles har denna separata kartklientåtkomst; övriga appfiler och administrativa API:er kräver login.

Före publicering kan du välja *Ljusvinkel* (15–80°, standard 35) och *Reliefstyrka* (0,5–3, standard 1,7). **Publicera om** bygger om tidigare kataloger med den valda stilen. XYZ kan begäras till zoom 22. Nivåer över den lagrade pyramidens maxzoom beskärs och förstoras vid anrop så kartan förblir synlig vid exempelvis 1:500, men det uppstår ingen ny terrängdetalj. Även kartklienten måste tillåta den aktuella zoomnivån.
